# Deterministic SPIFFS installation images

`tools/build_spiffs_image.py` creates a complete, ready-to-mount filesystem image
for either selected modified reference layout. It performs host-side formatting
explicitly. Firmware mounting does not format a blank or failed filesystem.

| Profile | Flash layout | Filesystem offset | Image bytes | Logical block | Page |
| --- | --- | ---: | ---: | ---: | ---: |
| `esp8266-2m` | Pinned ESP8266 2 MiB linker reference | `0x100000` | `0xFB000` | 8192 | 256 |
| `esp32-4m` | Modified 4 MiB reference, application below `0x200000` | `0x200000` | `0x200000` | 4096 | 256 |

The ESP8266 region contains 125 whole logical blocks and one final unused 4 KiB
erase sector. The image preserves that sector as `0xff`. The ESP32 partition is
the selected modified reference layout; it is not an inferred OEM partition map.
The package owner must use the same application/partition layout and reject any
overlap. This tool creates files; it does not flash hardware.

## Format and ABI evidence

The native formatter compiles all five unmodified SPIFFS C sources bundled with
the pinned ESP8266 2.4.1 SDK. Every dependency is checked against its recorded
SHA-256 identity. The ESP32 profile explicitly selects its SDK's metadata length,
magic-length option, GC limit, copy buffer size and object-table alignment.

`dependencies/spiffs-format-abi.json` records packed type sizes and member offsets
read from the **actual pinned ESP32 `libspiffs.a` DWARF**, not from a guessed
header. `validate_spiffs_format.py` regenerates this witness from
`spiffs_nucleus.o`. It also compiles a constant-layout probe with each pinned
Xtensa compiler and compares the extracted target object values to the native
formatter. The target object is not executed for this layout check.

| On-flash field | ESP8266 | ESP32 |
| --- | ---: | ---: |
| Object/block/page/span index bytes | 2 each | 2 each |
| Common page header bytes | 5 | 5 |
| Common header object/span/flags offsets | 0 / 2 / 4 | 0 / 2 / 4 |
| Object header bytes | 46 | 49 |
| Object length/type/name offsets | 8 / 12 / 13 | 8 / 12 / 13 |
| Object name allocation | 32 | 32 |
| Metadata bytes / offset | 0 / absent | 4 / 45 |
| Subsequent index-page header bytes | 8 | 8 |
| Object index table alignment option | 1 | 0 |
| Magic includes filesystem length | No | Yes |

The alignment option matters: using the ESP8266 default with four metadata bytes
produces a 50-byte object header. The actual ESP32 SDK requires 49 bytes. The
formatter rejects a native layout that differs from the verified profile.
The archive's `spiffs_erase_block` instructions also confirm the ESP32 magic
formula and location: the 16-bit value is `0x0529 ^ page_bytes ^
(block_count - block_index)`, stored four bytes before the end of the lookup
page; erase age occupies its final two bytes. The witness pins relevant original
function sections as well as the full SDK object.

This is native execution of the pinned SPIFFS implementation with verified
ESP32 packed-format compatibility. It does not claim execution of the ESP32
filesystem binary, physical flash validation or an OEM layout.

## Empty image and explicit staged files

The default image is formatted and empty. The shared engine writes its initial
configuration, sequence and history records on first boot. No API key or Wi-Fi
credentials are generated by this tool.

```sh
python firmware/common/tools/build_spiffs_image.py \
  --profile esp8266-2m \
  --esp8266-sdk /path/to/esp8266-2.4.1 \
  --output firmware/common/build/ferm-spiffs.bin \
  --report firmware/common/build/ferm-spiffs.json

python firmware/common/tools/build_spiffs_image.py \
  --profile esp32-4m \
  --esp8266-sdk /path/to/esp8266-2.4.1 \
  --esp32-sdk /path/to/arduino-esp32-pinned \
  --output firmware/common/build/esp32-spiffs.bin \
  --report firmware/common/build/esp32-spiffs.json
```

Optional `--file /pb/KEY=/local/path` arguments copy explicitly supplied bytes.
The namespace and key limits match `VerifiedStorage`: `/pb/`, followed by 1–23
ASCII letters, digits, underscores or dots; no leading/trailing dot, traversal,
path separators, or reserved `.tmp`/`.bak` suffix. Duplicate names are rejected.
`/pb/api.key` must contain exactly 64 lowercase hexadecimal bytes. A staged
`/pb/network.a` or `.b` is the versioned `Records` container produced by
`Provisioning`; the formatter preserves its supplied contents. The engine still
validates record version, generation, checksum and network fields when loading.
Other valid logical keys can restore explicitly supplied engine files.

Staged files are copied to a private temporary snapshot before formatting, so a
changing input cannot invalidate readback. Any image containing staged inputs
and its optional report receive mode `0600`. Reports contain logical names and
lengths, never credentials or source paths. Such images are private provisioning
artifacts and must not be included in public reference packages. Empty images
contain no credentials. The output is replaced only after all verification
succeeds; input or formatting failure leaves an existing output untouched.

## Verification

For every image, the native implementation explicitly formats, mounts, writes,
flushes, checks, reads all files, unmounts, remounts and reads everything again.
The physical boundary models NOR programming with bitwise-AND writes and 4 KiB
erase alignment. Metadata uses epoch zero; no host clock or random input enters
the image. Input order is sorted, making rebuilds byte-for-byte deterministic.

A separate Python decoder traverses the block lookup tables, validates magic,
packed page headers and finalized flags, follows all object/index/data pages,
and reconstructs every file byte. It rejects unreferenced live pages, unexpected
names, inconsistent lengths and changes in the unused trailing region. This
independent traversal uses the SDK-verified packed layout.

`analysis/spiffs-image-validation.json` records both empty and staged images,
deterministic rebuild hashes, the two target layout probes and the original
SDK DWARF witness. Ten synthetic staged files cover empty files, page boundaries,
the maximum namespace length, a 70,001-byte multi-index object, a synthetic API
key and a synthetic versioned network record. The suite also rejects corrupted
block magic, invalid paths and malformed explicit API keys.

```sh
python firmware/common/tools/validate_spiffs_format.py \
  --esp8266-sdk /path/to/esp8266-2.4.1 \
  --esp32-sdk /path/to/arduino-esp32-pinned \
  --esp8266-toolchain /path/to/xtensa-lx106-elf \
  --esp32-toolchain /path/to/xtensa-esp32-elf \
  --write-report
PICO_ESP8266_SDK=/path/to/esp8266-2.4.1 \
PICO_ESP32_SDK=/path/to/arduino-esp32-pinned \
  python -m unittest discover -s firmware/common/tests -p 'test_spiffs_image.py' -v
```
